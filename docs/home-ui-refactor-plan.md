# 2FAS 主界面重构计划

状态：第 3 版已实施，等待提交与合并。

分支：`feature/ui-refactor`

选定方向：第 3 版“标题下拉 + 紧凑卡片”。

参考项目：[Stratum Auth](https://github.com/stratumauth/app)

## 1. 已确认需求

1. 经典主界面与焕新主界面并存，在“设置 > 外观”中选择“经典”或“焕新”。
2. 两套主界面共用同一份令牌、分组、排序、备份和同步数据，不复制数据库或业务逻辑。
3. 保留内置默认分组，并将它在两套界面中统一显示为“默认”。
4. 焕新界面采用第 3 版：左上角显示当前分组名称和下拉箭头，令牌使用紧凑卡片及底部倒计时进度条。
5. 完整保留应用内通知中心、未读状态、后台内容获取和浏览器扩展系统推送；仅在焕新界面隐藏通知图标，经典界面保持原样。
6. 主动拉取采用用户提供的 `中信数据拉取.svg` 云端数据拉取图标，不再使用现有 `Refresh` 或通用下载图标。
7. 主动拉取按钮位于右下角新增按钮左侧。
8. 条目更多菜单改为参考图中的底部操作抽屉。
9. 分组管理增加参考图中的“指定条目”界面，用流式标签批量选择该分组包含的令牌。
10. 设置页面其余内容和现有 2FAS 颜色风格保持不变。
11. 不移植 Stratum Auth 的图标包功能。

## 2. 设计原则

- 借鉴 Stratum Auth 的信息架构和交互，不直接复制其 C#、XML、图片或蓝紫色主题。
- 经典与焕新是同一功能的两种展示方式，任何数据变更必须立即反映到另一种界面。
- 优先复用现有 Repository、ViewModel 事件、导航和安全验证流程。
- 焕新界面只减少视觉占用，不删除复制、HOTP、隐藏验证码、下一验证码、长按和倒计时等能力。
- 数据兼容优先于一次性清理：不为了界面改版破坏现有备份、Google Drive 同步、WebDAV 云备份或上游合并能力。

## 3. 参考代码结论

Stratum Auth 的主界面优势来自以下组合：

- `activityMain.axml`：令牌列表、紧凑顶栏、底部操作栏和固定新增按钮。
- `MainActivity.cs`：保存当前分类，分类切换后更新标题、刷新列表并滚动到顶部。
- `MainMenuBottomSheet.cs` / `sheetMainMenu.axml`：分类选择与次级操作集中在底部抽屉。
- `sheetAuthenticatorMenu.axml`：条目操作以底部抽屉呈现。
- `sheetAssignCategoryEntries.axml`：使用流式条目标签批量指定分类内容。
- `menu/bottom.xml`：搜索入口从顶栏移到底部，扩大令牌列表可见空间。

本方案选用第 3 版布局，但继续使用 2FAS 的数据语义、导航和红色主题。

## 4. 经典/焕新共存方案

### 4.1 设置模型

新增独立设置枚举，不与现有令牌密度 `ServicesStyle` 混用：

```kotlin
enum class HomeUiMode {
    Classic,
    Refreshed,
}
```

- `Classic`：当前主界面布局。
- `Refreshed`：第 3 版焕新布局。
- 首次加入该设置时默认 `Classic`，避免升级后未经用户选择突然改变主界面。
- 用户选择后写入现有 `SettingsLocalSource`，切换立即生效并在重启后保留。
- 该设置仅控制主界面 Composable，不进入令牌备份文件，也不参与云同步。

### 4.2 页面组织

- `ServicesRoute` 继续作为唯一入口，并继续消费同一份 `ServicesViewModel` 状态和事件。
- 当前 `ServicesScreen` 原样整理为 `ClassicServicesScreen`，避免在大量条件判断中维护两套布局。
- 新增 `RefreshedServicesScreen`，只负责新的展示和交互布局。
- 两个页面共用搜索、排序、主动拉取、新增、复制、编辑、删除和分组更新回调。
- 切换模式时保留当前搜索词和业务状态；列表滚动位置允许分别保存。

### 4.3 设置入口

在现有“设置 > 外观”页面增加一项：

- 标题：`主界面样式`
- 当前值：`经典` 或 `焕新`
- 点击后使用现有 `ListRadioDialog` 选择。

除这一项外，设置页面的布局和功能不重构。

## 5. 默认分组

现有 `GroupsRepositoryImpl` 会合成一个 `id = null` 的内置分组，现有令牌的 `groupId = null` 也归属于它。本轮保留这一数据约定：

- 内置分组在经典与焕新界面中都显示为 `默认`。
- 不创建新的数据库分组 ID，不迁移现有令牌的 `groupId`。
- 不允许删除、改名或移动内置默认分组。
- 新增令牌在未显式指定分组时继续进入默认分组。
- 备份映射仍忽略 `id = null` 的内置分组，保持现有备份格式兼容。
- Google Drive 同步、WebDAV 云备份和本地导入恢复不改变分组协议。

焕新界面的筛选状态明确区分“全部”“默认”和自定义分组：

```kotlin
sealed interface SelectedGroup {
    data object All : SelectedGroup
    data object Default : SelectedGroup
    data class Custom(val id: String) : SelectedGroup
}
```

## 6. 焕新主界面

### 6.1 顶栏

- 左侧显示当前分组名称和小号向下箭头，例如 `全部⌄`、`默认⌄`、`工作⌄`。
- 整个标题区域可点击，打开分组选择底部抽屉。
- 右侧只保留排序图标。
- 焕新界面不显示通知图标和未读红点，但不删除通知中心、导航、未读状态或后台逻辑。
- 顶栏高度保持紧凑，列表紧接顶栏开始。

### 6.2 分组切换

- 点击标题打开底部抽屉，顺序为 `全部`、`默认`、用户自定义分组。
- 当前项使用 2FAS 的淡红 `primaryIndicator` 背景和主色标识。
- 点击后立即关闭抽屉、更新标题、刷新令牌列表并滚动到顶部。
- `全部` 展示所有令牌，不插入分组标题。
- `默认` 展示 `groupId = null` 的令牌。
- 自定义分组展示对应 `groupId` 的令牌。
- 删除当前自定义分组后自动切换到 `默认`。

### 6.3 令牌卡片

焕新模式不直接复用经典模式的整行 `DsService` 外观，而是新增专用的紧凑卡片组件，但复用相同的 `ServiceState`：

- 低圆角、低间距的深色表面，不使用夸张阴影。
- 左上区域显示现有 2FAS 图标或两字母标签。
- 中间显示名称、账户信息和大号验证码。
- 右上角显示三点更多按钮。
- 卡片底边显示细的倒计时进度条，临近过期时沿用现有主色变化规则。
- HOTP 条目用递增按钮替代倒计时条。
- 隐藏验证码时继续使用现有隐藏/显示规则。
- 默认和紧凑令牌密度设置仍然生效，但只调整卡片高度、字体和内间距。
- 通过稳定高度和约束尺寸避免验证码、长账户名或大字体导致跳动、裁切和按钮重叠。

### 6.4 底部操作栏

- 左侧：主菜单、搜索。
- 右侧：主动拉取、新增令牌。
- 主动拉取严格位于新增按钮左侧，两个按钮使用稳定尺寸和固定间距。
- 新增按钮继续使用 2FAS 红色主色。
- 主动拉取使用用户提供的 `F:/Downloads/Browser/中信数据拉取.svg`：云朵轮廓内带双向数据拉取箭头。
- 实施时将 SVG 的两个 `path` 精确转换为项目内 Android Vector Drawable，例如 `ic_browser_request_pull.xml`；应用运行时不依赖下载目录中的源文件。
- Vector Drawable 使用单色路径并由 Compose `Icon` 统一着色，以适配深色、浅色和动态颜色；不再使用 `MdtIcons.Refresh` 或通用下载图标。
- 图标无文字时提供 `拉取浏览器请求` 的无障碍描述和长按提示。
- 拉取中显示小型进度指示器并禁止重复点击。
- 未绑定浏览器扩展时隐藏主动拉取按钮，不留下空占位。

### 6.5 搜索和排序

- 点击底栏搜索后，顶栏临时切换为现有搜索输入状态并自动聚焦。
- 搜索范围限定在当前分组；当前分组为 `全部` 时搜索所有令牌。
- 返回键优先清空搜索，再退出搜索。
- 排序继续使用现有“字母顺序/手动”选项，不新增复制次数字段。
- 手动排序只改变当前分组内的顺序，不隐式改变令牌所属分组。

## 7. 条目操作抽屉

点击卡片右上角三点或长按卡片，打开参考图风格的底部抽屉：

- 标题：`编辑`
- `编辑详情`：打开现有令牌编辑页。
- `更改图标`：打开现有图标/标签选择能力，不接入 Stratum 图标包。
- `指定分组`：打开单选分组选择器，可选择默认分组或任一自定义分组。
- `显示二维码`：复用现有安全验证和二维码展示流程，不绕过应用锁。
- `删除`：使用危险色；确认后沿用 2FAS 现有逻辑移入回收站，而不是物理删除。

交互约束：

- 抽屉中的每个操作使用现有 Material 图标，不使用文字字符模拟图标。
- 删除操作与其他操作留出分隔距离。
- 打开子页面后先关闭抽屉，避免多个 Modal 叠加。
- 经典模式保留当前长按详情交互；是否也接入新抽屉作为后续独立决定，不作为焕新模式首版阻塞项。

## 8. 分组“指定条目”界面

从分组管理进入某个自定义分组后，提供 `指定条目` 操作，并打开参考图风格的全屏底部抽屉：

- 顶部使用拖拽手柄和标题 `指定条目`。
- 主区域使用 `FlowRow` 展示所有非回收站令牌。
- 每个标签显示令牌图标、名称；名称重复时附加账户信息以便区分。
- 已属于当前分组的条目使用淡红填充与主色边框。
- 未选择条目使用透明/表面背景和中性边框。
- 底部固定 `确定` 按钮；编辑过程只改本地临时状态，点击确定后一次性提交。
- 返回或下滑关闭时放弃未保存选择。

当前 2FAS 是单分组模型，因此批量指定遵循以下规则：

- 选中一个原本属于其他分组的令牌，会在确认时移动到当前分组。
- 取消当前分组中的令牌，会在确认时移动到内置 `默认` 分组。
- 一个令牌不能同时属于多个分组，本轮不改为多对多关系。
- 默认分组不提供“删除”，但可使用同一指定条目界面批量接收令牌。
- 提交作为一次批量操作，避免逐条触发多次云同步和云备份。

## 9. 通知功能兼容策略

通知功能保持完整，不做数据、导航或后台逻辑删除：

- 保留 `Screen.Notifications`、`NotificationsScreen`、`NotificationsViewModel` 和 Koin 注册。
- 保留 `ServicesUiState.hasUnreadNotifications` 与 `ServicesViewModel` 的未读订阅，供经典界面继续显示徽标。
- 保留 `MainViewModel` 的远端通知内容获取。
- 保留 `OnAppStartWork` 的周期提示内容生成。
- 保留 `data:notifications`、Room 表、DAO、Repository 和本地/远端数据源。
- 保留 FCM、Android 系统通知权限、浏览器扩展通知渠道和审批操作。

两套界面的差异仅在展示层：

- 经典界面继续显示通知图标、未读红点，并可正常进入通知中心。
- 焕新界面的顶栏不渲染通知图标和未读红点。
- 从焕新界面切换到经典界面后，未读状态和通知内容仍然完整可见。
- 不因焕新界面隐藏入口而停止获取、删除或自动标记通知。

## 10. 经典模式边界

经典模式以当前代码为基线，保持以下内容不变：

- 顶部搜索框、现有列表和展开式分组结构。
- 当前底部“令牌/设置”导航。
- 当前 `DsService` 默认/紧凑样式。
- 当前分组管理和跨分组拖拽逻辑。
- 当前新增、搜索、排序、复制和长按行为。

经典模式只允许一项可见变化：内置分组文案改为 `默认`。通知图标、未读徽标、通知中心和后台行为全部保持不变。

## 13. 测试重点

- `HomeUiMode` 默认经典、保存后重启保持、运行时切换无崩溃。
- 两套界面对同一令牌增删改后立即一致。
- “全部/默认/自定义分组”筛选准确，焕新界面首次进入及删除当前分组后均回到“全部”。
- 批量指定条目遵守单分组语义，并且只触发一次批量同步/备份事件。
- 焕新卡片在默认/紧凑、TOTP/HOTP、隐藏/显示验证码下均正确。

- 焕新界面不显示通知图标，切换回经典后未读状态不得丢失。
- 浏览器扩展 FCM 推送、手动拉取和系统通知审批继续正常。
- 经典模式除“默认”文案外无视觉/行为回归。

## 14. 验收标准

- 用户可在“设置 > 外观 > 主界面样式”中切换经典/焕新。
- 默认进入经典模式，用户选择焕新后持久生效。
- 焕新模式与选定第 3 版一致：标题分组下拉、紧凑卡片、底部进度条和横向并列操作按钮。
- 两套模式都显示“默认”内置分组，并共用同一份分组数据。
- 焕新界面不显示通知图标；经典界面的通知入口、未读红点和通知中心保持原样。
- 应用内通知内容、周期提示和浏览器扩展 FCM/Android 系统通知均保持正常。
- 主动拉取使用用户指定的云端数据拉取 SVG 图标，且始终位于新增按钮左侧。
- 条目操作抽屉包含编辑详情、更改图标、指定分组、显示二维码和删除。
- 分组可通过流式标签批量指定条目，长名称不溢出，确定/取消语义明确。
- 设置页除新增主界面样式选项外保持原样。
- 经典模式可随时作为稳定回退路径使用。
